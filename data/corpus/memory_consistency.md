# 多 Agent 记忆与一致性(本地语料 · 演示用)

多个 Agent 同时运行时,记忆为什么会串台?默认场景下每个 Agent 绑定专属 sessionId,
私有记忆按 (session_id, agent_id) 命名空间隔离,框架维护会话索引表并强校验,A 只能读
取自己会话下的数据,因此不会互相覆盖。一旦开启"记忆池化"(多个会话共用底层存储实例),
而 sessionId 传错或索引没有强校验,读请求就会拿到别的 Agent 的记忆——脏读,即记忆串台。

共享全局记忆(黑板)是解决多 Agent 互通信息的机制:所有 Agent 都能读取公共结论,一般
只开放发布权,不直接覆盖他人私有记忆。工程上,黑板合并必须走纯 reducer:按向量时钟
合并且不丢值。

并发写冲突的处理分两级:向量时钟给出偏序——分量全相等为 equal,一方全大则为支配,
互不大小则并发。并发即冲突:同一分片(同 key、同上下文)的两个并发写需要仲裁。若两次
写入意图不冲突,执行版本偏移转换(rebase):把后写者的意图套到最新版本上重写;若意图
真冲突,由仲裁者裁决胜者或要求重写。所有写入带确定性幂等 ID(uuid5 派生),重试与重放
不会产生重复记录;操作日志追加式保存,迟到的 Agent 按自己上次同步的水位线拉增量,
补齐历史。

LWW(last-writer-wins)兜底必须用 HLC(混合逻辑时钟)给出全序:墙时间相同或回拨时用
计数器打破平局,再以 agent_id 保证严格全序,避免同一毫秒内出现随机胜者。
