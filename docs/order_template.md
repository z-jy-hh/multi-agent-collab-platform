# R17 开工令模板（C3）· docs/order_template.md

> C3（R17 设计 §评估-B/C）：所有开工令 / 修复令 / 复核令必须包含以下五个
> 必填段。缺任何一段 = 令无效，执行方可直接拒收（打回补段）。
> 使用方法：复制本文件，逐段填写，保存为
> `workorder_<阶段>_<主题>.md` 后随令下发。
> 五段之外的补充段（探针脚本、判据附录、历史对照）允许追加，但不允许替代。

---

## 段一 · 任务（做什么）

- 令名：【R17 <阶段> 开工令 · <主题> · 执行方：<执行者>】
- 背景与动机（引用复核/评审编号，一行一条）：
- 交付物清单（文件级，逐个列出新增/修改/删除）：
- 明确不做的事（范围外，防扩散）：

## 段二 · 判据（怎么算做完——可机检）

- 验收命令（逐条，含预期退出码/预期输出摘要）：
  ```
  <命令>   # 期望: <可判定的结果>
  ```
- 反向/判别判据（必须包含至少一条"做了假修必然变红"的判别用例）：
- 全量回归口径（四口径 ①②③④ 或等价串行测量）与 layercheck/clean/frozen：
- 数字基线（当前 passed/skipped，禁止引用旧基线冒充）：

## 段三 · 红线（绝不能碰）

- 目录红线（如：`core/ dsh_bridge/ crews/ configs/ prompts/` 不改）：
- 行为红线（既有对外契约/字节级冻结物不变；如需扩围，先令后行）：
- 依赖红线（不得新增重量级依赖；不得引入影子状态）：

## 段四 · 回滚（必须可回滚）

- 回滚操作（精确命令序列）：
  ```
  git revert <本令全部提交的区间>   # 期望: exit 0 + worktree 干净
  ```
- 回滚后验证（回到哪个基线提交、跑哪条最小判据确认）：
- 回滚-of-回滚（重放验证，防单向门）：

## 段五 · 报告（交付时交什么）

- 报告路径：`reports/R17_<阶段>_report.md`
- 必含内容：逐条判据的**原始输出**（命令 + 退出码 + 关键行，禁止散文代替）、
  本令全部提交 hash 列表、诚实登记（未交付/部分交付项必须显式列出，
  不得静默省略）、遗留风险与建议下一令。
- 报告反证规则：复核方将**不采信自述**，以独立实跑为准；报告中的每条
  命令必须可原样重放。

## 门禁顺序（固定，R17 P2-FIX 令 F5/D3 起生效 · 每一令照此执行）

1. **报告先 git 跟踪，再跑 fourenv**：污染类断言以 `git status --porcelain`
   为准，未跟踪的报告文件会打红 clean/full 门（P2 画布令实测：首轮 fourenv
   因此整体作废重跑）。
2. **每条判据至少在「默认全量收集顺序」下验证过一次**（`pytest -q`，exit=0）；
   单文件绿不作为门禁结论，报告中必须写明全量顺序输出的落点（文件 + 行）。
3. **字节等价类判据必须剥离并钉死行为开关类宿主 env**——不得只写"已剥离宿主
   env"，报告必须**显式列出被剥离/钉死的 env 名单**（D3）。最低名单：
   `PYTHONPATH / PYTHONIOENCODING / PYTHONUTF8`（剥离）+
   `DISPATCH_HETERO / AGENT_REGISTRY / WB_ENABLED / GATE_ENV / WB_GATE_ENV /
   R16_TRACE / DSH_HOME / WB_AUDIT_DIR / REDACTION_ENABLED /
   DISPATCH_BACKEND_OVERRIDES / DISPATCH_CONSENT_TOKEN / DISPATCH_DATA_OPT_IN /
   DISPATCH_COUNTERS_ALLOW_CORRUPT`（显式清除或钉死）。
   实证背景（R17 P2-FIX）：`DISPATCH_HETERO=1` 会令 `run_topology` 多发
   `hetero_dispatch_*` 事件，使 off 态字节等价判据随宿主 shell 漂移；
   强隔离场景建议直接用 env 白名单（只放行 `PATH/SystemRoot/SystemDrive/
   TEMP/TMP/USERPROFILE/APPDATA/LOCALAPPDATA` + `PYTHONHASHSEED=0`）。
4. **并行扇出拓扑的字节等价判据必须固定线程交错序**（P2-FIX 增补）：worker
   扇出在多线程下 `blackboard_write/agent_output` 交错非确定（内容相同、
   顺序漂移，摘要随之漂移）；判据侧夹具须用同步闸（等先手节点的落板事件）
   钉死与基线一致的交错序。
5. **命令输出为空 = 失败**（P3 令 B-6 起）：任何命令（含门禁）输出为空一律
   视为失败，不得当作通过；门禁必须回显**命令绝对路径 + 非空输出 + 耗时**。
   实证背景（P3 期）：`~/.local/bin/env` 是 uv 的 PATH shim 脚本而非 coreutils
   env，裸 `env CMD` 静默不执行且返回 0，曾使两次"全量跑"实际没跑——凡用
   `env` 必须写绝对路径 `/usr/bin/env`。
6. **命令卫生（工作目录显式化，P3 令门禁规则 6）**：每条门禁/判据命令必须
   **显式带工作目录**（`cd <绝对路径> && …` 或平台等价物，建议固化为带
   `cd` 的包装脚本），并在输出中**回显 `pwd` / `rootdir`**；只给命令、不给
   工作目录 ⇒ 该条命令无效。实证背景（P3 期两例）：`cd` 前缀连续丢失 4 次，
   rootdir 落在宿主会话区致同一命令全报 file not found。
7. **规则 7（本令新增，来自 P3 层违规）**：新增测试文件按层规则落点 —— `tests/unit` 属 core scope，
   **禁止顶层 import `graphs`/`api`**；**跨层判据一律放 `tests/integration`**。
   （照录自 MEM1 令 `93fef01e3a1761a1` 段三，未改写措辞；ACCT2 令 `09a74ff3b264f916` A-4 一并补入模板——
   缺口根因 = MEM1 令的文件白名单不含本模板，写不进去，非漏做。DSH 已按 A-5 认领该漏检，候选错误事件
   `FM-SPOTCHECK-GAP`。）
8. **复核方抽检（ACCT2 令新增，门禁规则 8）**：每轮交付，执行方**抽检复核方 1–2 条结论**，逐条给
   **"复现/不复现 + 原始输出"**，并写进报告；**抽检按「错误代价 × 概率」排序**（不按纯随机），并
   **登记提名与理由（留痕）**；**复核方可于下一轮要求补抽**（防"提名被操纵"）；**抽检须在交付前完成**
   （以便影响本轮），且**复现失败必须如实登记**，不得柔化措辞。首次执行：ACCT2 轮（抽检 DSH 的
   P3"零足迹普查 = 0"与 SPI"15 锚点全缺"两条结论）。

## 命名与所有权（P3 令 F-3 增节；一行级，细则见 `docs/order_report_index.md` §七）

- 令 = `workorder_<线>_<slug>.md`；报告 = `<线>_<轮>_report.md`；复核 = `..._review_by_<作者>.md`；
  共享文件（模板/工具/三本账/报告）的**谁可改**与**append-only 规则**一律以
  `docs/order_report_index.md` §七的表为准，本模板不重复维护。
