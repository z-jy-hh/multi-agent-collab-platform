# UI 设计文档模板 · docs/ui_design_template.md

> 用途：任何**界面级**设计（新页面 / 新面板 / 组件重构 / 视觉改版）都按本模板出文档。
> 使用方法：复制本文件 → 保存为 `docs/<主题>_ui_plan_v<版本>.md` → 逐段填写。
> **不许跳段**：段 3（token）、段 6（组件状态矩阵）、段 9（无障碍）、段 10（可机检判据）缺失即为不完整设计。
> 配套技能：`ui-ux-pro-max`（本地已装，pin `1a2c459…`，MIT）—— 风格/配色/排版/UX 规则用它检索，**结果是建议，不得覆盖仓库规则**。

## 段 1 · 目标、范围与明确不做
- 要解决的用户问题（一句话）+ 成功长什么样（可观察）：
- 本期范围：**逐项列出**（信息架构 / 交互 / 视觉 / 状态）
- **明确不做**（防扩散；至少写 3 条）：
- 与既有 UI 的关系（改哪、留哪、不动哪）：

## 段 2 · 现状事实（**带锚点，禁臆测**）
- 承载文件与规模：`<file:line>`（行数/字节）
- 现有可复用件：`<id/class:line>`、已有模态/钩子/工具函数
- 数据面：端点 + **真实样本**（字段形状从真实数据核验，不靠猜）
- **硬约束（先抄下来）**：测试锚点（必留 id / 禁词 / 契约字面）、既有 CSS 变量层、无框架/无构建链等
- 技能检索记录：查询词 + domain + **命中标题**；**0 命中要如实写"无命中"并只重试一次**

## 段 3 · 设计 token（**语义命名，组件内禁裸 hex**）
- 风格定位（技能命中的 style 名 + Best For 依据）：
- 颜色：`--bg/--card/--fg/--muted/--border/--ring/--primary/--accent/--destructive` + **语义色**（状态/类型）
  · 约束：正文与次要文本在**各底色上对比 ≥4.5:1**；`--muted-fg` 只用于非关键元信息
- 字体：UI sans / mono（mono 给 id、键、计数）+ `tabular-nums`；基准字号与行高；行长 ≤ 90ch
- 间距/圆角/动效：4-8 节奏；`--t-fast/base/slow`；`prefers-reduced-motion` ⇒ **时长归零**
- **依赖决策**：是否引 webfont/图标库？（默认**不引**：离线自包含优先；引则写明失败降级）

## 段 4 · 信息架构与布局
- 结构图（层级 + 区块 id）：
- 尺寸与密度（宽/高、滚动容器、max-height）
- 首屏可见什么、什么需要一次点击（防"信息倾倒"）
- **溢出策略**：长串（id/key/路径）→ `min-width:0 + nowrap + text-overflow:ellipsis`，图标 `flex:none`；
  **不得**用 `overflow:hidden` 硬裁内容；正文截断必须配"展开/查看全文"

## 段 5 · 数据映射（若为数据驱动界面）
- 事件/字段 → 渲染件的映射表（逐行）
- **缺失与异常的数据如何显示**（显式占位，不许静默空白）
- 缓存键与失效（按什么 id 分桶、何时清）
- **转义与注入**：一切外部字符串先转义；禁止 `innerHTML` 拼接未转义数据；正文用 `textContent`
- 敏感值（如脱敏掩码 `⟨REDACTED:…⟩`）**原样显示，不解读不还原**

## 段 6 · 组件清单与状态矩阵（**每件必填四态**）
| 组件 | 规格 | 默认 | hover | focus-visible | disabled/异常 |
|---|---|---|---|---|---|
| … | … | … | … | … | … |

- 图标：统一尺寸/线宽/同一族；**装饰性图标 `aria-hidden`**；**不得用 emoji 当图标**
- 徽标/标签：短标签不换行不裁字（集合用换行 + 间距）

## 段 7 · 交互与键盘
- 焦点：所有可交互元素有**可见焦点环**（不得 `outline:none` 无替代）
- 模态/抽屉：焦点陷阱 + `Esc` 关闭 + **焦点归还触发元素** + `role="dialog" aria-modal`
- Tab 顺序 = 视觉顺序；滚动内容**不被 sticky 条遮挡**
- 加载：近即时（<150ms）不显示加载视觉；超过则骨架 + `aria-busy="true"`
- 复制类操作：给出 `role="status"` 的短提示
- 动效：只做能表达含义的（进入用 opacity 120–160ms；不做位移+缩放组合）

## 段 8 · 四态与边界（**空 / 加载 / 失败 / 就绪**）
- 空态：一句解释 + 一个动作（禁"空白屏"）
- 加载态：可判定的标记（`data-*` 或 `aria-busy`）+ 不闪烁
- 失败态：**就近**报错 + 重试按钮（不用顶部飘条代替）
- 就绪态：数量/时间等元信息；大数据的**展开策略与滚动锚点**（追加内容不得把用户视线推走）

## 段 9 · 无障碍清单（逐条打勾，缺项要写理由）
- [ ] 正文/次要文本对比 ≥4.5:1（**深浅两套底色分别测**）
- [ ] 颜色**永不单独**承载语义（必须配文本或形状）
- [ ] 全部可交互元素键盘可达 + 焦点可见 + 焦点不被遮挡
- [ ] 模态焦点陷阱 / Esc / 焦点归还
- [ ] `prefers-reduced-motion` 下无必要动效
- [ ] 表单/按钮标签可读（禁 placeholder 当唯一标签）
- [ ] 屏幕阅读器顺序 = 视觉顺序；装饰元素隐藏

## 段 10 · 可机检验收判据（**逐条给命令 + 期望，交付时贴原始输出**）
- 每条写成：`<命令/脚本断言>` ⇒ 期望 `<可判定结果>`
- 必含：**红线类**（禁词 0 命中 / 必留 id / 契约字面）、**外链类**（无 webfont/CDN 请求）、
  **溢出类**（注入 200 字符断言 `scrollWidth<=clientWidth`）、**状态类**（四态标记可达）、
  **键盘类**（Tab 覆盖 + 焦点归还）、**动效类**（reduced-motion 时长 0）、**回归类**（既有测试与全量口径）
- **判别用例（“做了假修必然变红”≥1 条）**：例如"把白名单映射换成显示原名 ⇒ 禁词判据必红"、
  "把四态换成硬编码'已就绪' ⇒ 状态判据必红"
- 数字基线（当前 passed/skipped 等，**禁引用旧基线冒充**）

## 段 11 · 交付、回滚与二期
- 交付物：文件级清单（新增/修改/删除）
- 回滚：`git revert <提交>` + 回滚后最小验证（+ 回滚-of-回滚重放）
- 二期边界：什么明确留到下一期；需要先定的前置问题
- 变更记录：版本 / 日期 / 改了什么 / 为什么（只追加，不覆盖历史结论）

### 附 · 常见反模式（评审时优先查这些）
1. 用**消费级隐喻**套专业工具（聊天气泡 ↔ 运维控制台）——先问"用户要扫读还是要对话"
2. **颜色单独承载语义**（agent/状态/优先级只用颜色）
3. **长串溢出**（id/key/路径撑破容器）或被 `overflow:hidden` 悄悄裁掉
4. 只有"加载中"没有"空/失败"，或加载视觉在近即时操作上闪烁
5. **原文/原始标识直接进 DOM**（在禁词或安全约束下会被判据咬死）
6. 引入**外链字体/CDN**破坏离线自包含
7. 动效"到处都在动"或无视 `prefers-reduced-motion`
8. 判据全是"看起来不错"——**没有一条能咬死假修**
